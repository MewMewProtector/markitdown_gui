# markitdown_gui

Десктоп-приложение с графическим интерфейсом - обёртка над `markitdown[all]`.
Следит за выбранной папкой, подсвечивает новые поддерживаемые файлы,
позволяет конвертировать их в `.md`, просматривать результат с подсветкой
синтаксиса Markdown и (опционально) описывать картинки через LLM.

## Возможности

- Слежение за выбранной папкой (`QFileSystemWatcher`, debounce 500 мс).
- Drag-n-drop файлов и папок прямо в окно.
- Ручное добавление через диалог с фильтром по поддерживаемым расширениям.
- Конвертация выбранных файлов в пуле потоков (`QThreadPool` + `QRunnable`).
- Два режима предпросмотра: отрисованный документ и исходный Markdown с
  подсветкой синтаксиса. LaTeX в `$...$`, `$$...$$`, `\(...\)` и `\[...\]`
  преобразуется в MathML и работает офлайн.
- Современная боковая навигация, карточки настроек, индикатор стриминга и
  наглядная очередь файлов.
- Тёмная, светлая темы и тема "как система", фреймлесс-окно с кастомным
  заголовком, настраиваемые акцентные цвета.
- Журнал конвертаций в SQLite + экспорт CSV.
- Настройки MarkItDown: LLM (любой OpenAI-совместимый эндпоинт),
  Document Intelligence, Content Understanding, плагины, аудио, YouTube.
- API-ключ хранится через системное защищённое хранилище (`keyring`; на
  Windows — Диспетчер учётных данных), а не открытым текстом в SQLite.
- **Режим стриминга** - при включении любой файл, появившийся в
  папке сканирования **после запуска слежения**, ставится в очередь и
  автоматически конвертируется в `.md`. Результат записывается в
  заранее заданную **внешнюю** папку сохранения (не внутрь папки
  сканирования). Использует сохранённые `describe_images`, API key,
  base URL, модель и промпт без интерактивных подтверждений.
- **Описание картинок через LLM** на трёх уровнях:
  - **L1** - `.jpg` / `.jpeg` / `.png` файлы.
  - **L2** - картинки, встроенные в `.pdf`.
  - **L3** - картинки, встроенные в `.docx` / `.pptx` / `.xlsx`.
- Кэш описаний в SQLite (по SHA-256 от байтов картинки) - повторная
  конвертация той же папки не вызывает LLM.
- Безопасная работа с временными файлами: при извлечении картинок из
  документов создаётся свежая пустая папка в `%TEMP%`, которая удаляется
  в `finally` после конвертации - никакие чужие файлы не затрагиваются.

## Требования

- Python **3.10+**.
- Windows 10 / 11 (для сборки `.exe`).
- 200 МБ свободного места на диске.
- Для LLM-описаний: API-ключ любого OpenAI-совместимого сервиса
  (OpenAI, OpenRouter, Google Gemini, Ollama, Groq, DeepSeek и т.п.).
- Для транскрибации `mp3` / `m4a`: установленный FFmpeg, доступный через
  `PATH` (обычный `wav` может обрабатываться без него).

|---|---|
| Документы | `pdf`, `doc`, `docx`, `ppt`, `pptx`, `xls`, `xlsx`, `epub` |
| Текст | `md`, `markdown`, `txt`, `csv`, `json`, `xml`, `html`, `htm` |

## Подробная инструкция по использованию

### Шаг 1. Откройте вкладку "Настройки"

При первом запуске приложение само переключит вас на вкладку
**«Настройки»** и покажет тост с просьбой выбрать папку сканирования.

Вкладка содержит три секции:

- **Папки** - папка сканирования и (опционально) папка сохранения.
- **Внешний вид** - тема, акцентные цвета для светлой и тёмной темы.
- **MarkItDown / API** - параметры LLM, Document Intelligence,
  Content Understanding и плагинов.

### Шаг 2. Выберите папки

- **Папка сканирования** - папка, за которой приложение будет следить.
  Новые поддерживаемые файлы в этой папке автоматически появятся во
  вкладке «Файлы» с галочкой. Чтобы выбрать - нажмите **«Выбрать...»**
  справа от поля.
- **Папка сохранения** - папка, куда будут записываться результаты
  конвертации в `.md`. Если оставить пустой - `.md` файлы сохраняются
  рядом с исходниками. В режиме стриминга папка сохранения обязательна
  и должна быть вне папки сканирования (иначе режим не активируется).

### Шаг 3. (Опционально) Заполните параметры LLM

Если вы хотите описывать картинки через LLM - заполните поля в секции
**«MarkItDown / API»** (подробнее см. раздел "Как включить описание
картинок через LLM" ниже).

### Шаг 4. Сохраните настройки

Нажмите кнопку **«Сохранить»** внизу вкладки или **Ctrl+S** в любом
месте вкладки «Настройки». Сверху по центру появится зелёная пилюля
«Настройки сохранены» с галочкой (держится 4 секунды).

После сохранения приложение начнёт следить за выбранной папкой.

### Шаг 5. Добавьте файлы во вкладку «Файлы»

Три способа:

- **Drag-n-drop** - перетащите файлы или папки прямо в окно приложения.
- **«Добавить файлы...»** - откроется диалог с фильтром по расширениям.
- **«Добавить папку...»** - рекурсивно добавит все поддерживаемые файлы
  из выбранной папки.

Все новые файлы появятся в таблице с галочкой - значит они выбраны для
конвертации. Чтобы снять галочку - кликните по ней.

### Шаг 6. Запустите конвертацию

- Кнопка **«Выбрать все»** / **«Очистить»** в тулбаре вкладки «Файлы»
  управляет массовым выбором.
- Нажмите **«Преобразовать выбранные»** внизу вкладки.
- Если в пакете есть хотя бы одна картинка - появится компактный диалог
  с галочкой **«Описывать картинки (LLM)»**. Можно подтвердить или
  переопределить выбор прямо здесь.
- Прогресс виден в реальном времени в столбце статуса и в процентах
  внизу каждой строки. Для PDF с несколькими картинками прогресс
  идёт по каждой картинке отдельно - вы увидите движение от 25% до 80%.

### Шаг 7. Проверьте результат

- По завершении конвертации приложение автоматически переключится на
  раздел **«Предпросмотр»** и покажет отрисованный документ. Кнопка
  **«Исходник»** переключает на текст получившегося `.md`.
- Формулы вроде `$x_i^2$` и `$$\frac{a}{b}$$` отображаются с индексами,
  дробями и математическими символами, а не как обычная строка.
- Двойной клик по строке в таблице «Файлы» тоже открывает превью
  уже сконвертированного `.md` (если он есть).
- Вкладка **«Лог»** содержит полный список всех конвертаций со
  статусами и ошибками. Колонка «Ошибка» заполняется, если LLM не
  смог описать конкретную картинку - там видна точная причина
  (`HTTP 401: ...`, `таймаут (30с)`, `rate limit (429)` и т.п.).

### Шорткаты

- **Ctrl+S** на вкладке «Настройки» - сохранить настройки.

## Режим стриминга

В разделе **«Настройки → Папки»** есть галочка **«Стриминг: автоматически
конвертировать новые файлы в .md»**. Когда она включена:

- Обрабатываются **только** файлы, появившиеся в папке сканирования
  **после запуска слежения**. Файлы, лежавшие там изначально -
  базовая линия, они не конвертируются.
- При сохранении настроек приложение проверяет, что задана отдельная
  **внешняя** папка сохранения (она не должна совпадать с папкой
  сканирования и не должна находиться внутри неё). Если условие не
  выполнено - режим не активируется, остальные настройки сохраняются,
  а внизу вкладки «Настройки» появляется красное сообщение с
  объяснением.
- Исходный файл **никогда не перемещается и не удаляется**; в папку
  сохранения пишется только итоговый `.md`.
- Каждый новый файл ставится в **FIFO-очередь** и обрабатывается
  строго по одному. Если в папку сканирования одновременно упало
  несколько файлов с одинаковым базовым именем (например, из разных
  подпапок), результаты получают суффиксы `_1`, `_2`, ... без
  перезаписи.
- Перед запуском MarkItDown приложение ждёт, пока файл перестанет
  расти (две последовательные проверки `size`/`mtime` с интервалом
  ~1 с). Это защищает от чтения ещё не докачанного файла.
- Диалога «Описать картинки?» в стриминге **нет** - используется
  сохранённая галочка **«Описывать картинки (LLM)»** вместе с
  сохранёнными же `OpenAI API key`, `base URL`, `Model` и `Prompt`.
- При успешной конвертации результаты **не открывают** вкладку
  «Предпросмотр» и не меняют активную вкладку - приложение
  обновляет таблицу файлов и вкладку «Лог» в фоне. Если очередь
  пустая, программа вообще не привлекает внимание.
- Если файл исчез до того, как очередь дошла до него, или
  конвертация упала - строка помечается как «ошибка», показывается
  тост, очередь **продолжается**. Повторных попыток не делается
  (это намеренно: чтобы не дублировать LLM-запросы и `.md` файлы).
- Все попытки попадают в **вкладку «Лог»**, как обычно. Тост
  «Стриминг: ожидание N файл(ов)...» появляется при поступлении
  новых файлов.

### Типичный сценарий

1. **Настройки → Папки**: выбрать `C:\incoming` как папку сканирования,
   `D:\md-archive` как папку сохранения.
2. Поставить галочку **«Стриминг»** и **«Описывать картинки (LLM)»**
   (если нужно).
3. Заполнить параметры LLM (см. раздел «Как включить описание картинок
   через LLM»).
4. **Ctrl+S** для сохранения.
5. Скидывать файлы в `C:\incoming` (перетаскиванием, скриптами,
   почтовыми правилами, и т.д.) - в `D:\md-archive` появятся готовые
   `.md` с описаниями картинок.

### Отключение стриминга

Снять галочку **«Стриминг»** в Настройках, **Ctrl+S**. Все ещё не
запущенные задания из очереди отменяются и их файлы возвращаются в
режим «ожидание» во вкладке «Файлы», а уже выполняющееся задание
безопасно завершается. Новые файлы снова появятся во вкладке «Файлы»
для ручного запуска.

## Как включить описание картинок через LLM

Поддерживаются три уровня описания - все управляются **одной** галочкой
и используют одни и те же поля LLM:

| Уровень | Что покрывает | Где работает |
|---|---|---|
| **L1** | `.jpg` / `.jpeg` / `.png` файлы | Описание добавляется в конец `.md` блоком `# Description:` |
| **L2** | Картинки внутри `.pdf` | Описание группируется по страницам (`## Page N`) |
| **L3** | Картинки внутри `.docx` / `.pptx` / `.xlsx` | Описание плоским списком под `## Описания изображений - <имя_файла>` |

### Шаг 1. Получите API-ключ у одного из провайдеров

Любой OpenAI-совместимый эндпоинт подойдёт:

| Провайдер | base URL | Где взять ключ | Пример модели с vision |
|---|---|---|---|
| **OpenAI** | `https://api.openai.com/v1` | [platform.openai.com](https://platform.openai.com/api-keys) | `gpt-4o-mini`, `gpt-4o` |
| **OpenRouter** | `https://openrouter.ai/api/v1` | [openrouter.ai/keys](https://openrouter.ai/keys) | `google/gemini-2.0-flash-exp:free`, `google/gemini-2.5-flash` |
| **Google Gemini** | `https://generativelanguage.googleapis.com/v1beta/openai` | [aistudio.google.com](https://aistudio.google.com/app/apikey) | `gemini-2.0-flash`, `gemini-2.5-flash` |
| **Ollama** (локально) | `http://localhost:11434/v1` | ключ - любая строка, например `ollama` | `llama3.2-vision:11b`, `gemma3:4b` |
| **Groq** | `https://api.groq.com/openai/v1` | [console.groq.com](https://console.groq.com/keys) | `meta-llama/llama-4-scout-17b-16e-instruct` |
| **DeepSeek** | `https://api.deepseek.com/v1` | [platform.deepseek.com](https://platform.deepseek.com/api_keys) | vision пока нет - описание картинок работать не будет |

> **Важно.** Не все модели умеют vision. Если модель не поддерживает
> картинки на входе - в Логе будет `HTTP 400: ...invalid image...`.
> Список vision-моделей у каждого провайдера свой - ищите в его
> каталоге модели с пометкой "vision" или "multimodal".

> **Бесплатные тарифы** часто имеют ограничения:
> - OpenRouter `:free` модели могут быть медленными (очереди, cold start)
>   и упираться в rate-limit (429) при большом пакете картинок.
> - В приложении есть кэш по SHA-256 от байтов картинки: одна и та же
>   картинка описывается только один раз.

### Шаг 2. Заполните поля в Настройках

Откройте вкладку **«Настройки» → MarkItDown / API** и заполните:

| Поле | Что вводить | Пример |
|---|---|---|
| `OpenAI API key` | Ваш ключ от выбранного провайдера | `sk-or-v1-...` (OpenRouter), `AIzaSy...` (Gemini) |
| `OpenAI base URL` | Эндпоинт из таблицы выше | `https://openrouter.ai/api/v1` |
| `Model` | Имя vision-модели у провайдера | `google/gemini-2.0-flash-exp:free` |
| `Prompt` | Системный промпт для модели (см. ниже) | см. рекомендованный промпт |

### Шаг 3. Включите описание картинок

Под формой API стоит галочка **«Описывать картинки (LLM)»** - поставьте её.

Нажмите **«Сохранить»** внизу или **Ctrl+S**. Сверху по центру
появится зелёная пилюля «Настройки сохранены».

### Шаг 4. Запустите конвертацию

Перейдите на вкладку **«Файлы»**, добавьте файлы (картинки, PDF,
DOCX/PPTX/XLSX), нажмите **«Преобразовать выбранные»**.

Если в пакете есть хотя бы одна картинка - появится компактный
диалог с галочкой **«Описывать картинки (LLM)»**. Здесь можно
подтвердить или снять выбор - настройка синхронизируется с вкладкой
«Настройки».

### Шаг 5. Проверьте результат

В получившемся `.md` появится секция **«Описания изображений»**
(для L2/L3) или блок `# Description:` (для L1). Каждая описанная
картинка выглядит так:

```markdown
**Изображение: p1_i0.png**

> Описание от LLM: 1. Overview - A photograph of a brown dog...
```

Если LLM не смог описать картинку, вместо описания будет placeholder:

```markdown
> [не удалось получить описание изображения]
```

и точная причина попадёт в столбец «Ошибка» на вкладке «Лог».

### Рекомендованный промпт для описания картинок

Скопируйте этот текст в поле **«Prompt»** на вкладке Настройки -
он даёт наиболее полные и точные описания:

```
You are a meticulous image captioning specialist. Your job is to
produce exhaustive, accurate, neutral descriptions of images in English.

Core rules:
- Describe ONLY what is optically present. Never use external knowledge,
  and never invent text, numbers, labels, brands, or values you cannot
  clearly see in the image.
- If something is blurry, too small, or ambiguous, say so explicitly
  ("blurry in the background", "partially legible").
- Transcribe ALL visible text verbatim - signs, labels, screens, water-
  marks, logos, captions, handwriting. Note its position and color.
- Use neutral, precise language. No subjective adjectives ("beautiful",
  "stunning", "impressive"). Stick to observable facts.
- Be exhaustive: aim for 250-500 words. If the image is genuinely rich
  (a complex diagram, a UI screenshot, a busy street scene), go longer.
  Leave no visible detail undescribed.

Cover these categories in this order:

1. Overview - 1-2 sentences: what type of image this is (photograph,
   illustration, screenshot, diagram, chart, painting, 3D render, etc.)
   and its main subject.

2. Subjects - people, characters, animals: number, identity (only if
   inferable from visible cues such as a name tag), appearance, pose,
   facial expression, clothing, actions, approximate age, ethnicity
   (only if visually evident).

3. Objects & items - every distinct object: type, color, size relative
   to other objects, material (if apparent), condition, state (open/
   closed, on/off, new/worn).

4. Setting & environment - indoor/outdoor, location type, time of day,
   weather, season, background elements, architecture, landscape.

5. Composition & framing - camera angle, perspective, focal point,
   foreground/midground/background, layout (centered, rule of thirds,
   symmetric, asymmetric), aspect ratio.

6. Lighting & color - light source(s), direction, intensity, shadows,
   contrast, color palette, dominant colors, saturation, color
   harmony.

7. Text & OCR - every piece of visible text, transcribed verbatim, with
   approximate position, color, and relative font size. Include any
   partially legible text with that note.

8. Style & medium - photographic / illustrated / rendered / hand-drawn /
   vector, artistic style, technical qualities (depth of field, bokeh,
   film grain, noise, compression artifacts) if visible.

9. Mood & atmosphere - emotional tone conveyed by expressions, body
   language, lighting, and color. Descriptive, never evaluative.

10. Notable details - anything unusual, symbolic, or worth flagging that
    did not fit above.

Output format: Markdown with the numbered section headings above. No
preamble, no postamble, no "The image shows..." - start directly with
section 1.
```

> **Примечание.** Если хотите описания на русском - добавьте в начало
> промпта `Reply in Russian.` или замените `in English` на `in Russian`
> в первой строке.

### Решение проблем

| Симптом | Причина | Что делать |
|---|---|---|
| `HTTP 401: ...` | Неверный API-ключ | Перевыпустите ключ в кабинете провайдера |
| `HTTP 404: Model not found` | Неправильное имя модели | Проверьте имя в каталоге провайдера |
| `HTTP 429: Rate limit exceeded` | Упёрлись в лимит бесплатного тарифа | Подождите или перейдите на платный план |
| `HTTP 400: ...invalid image...` | Модель не поддерживает vision | Выберите другую модель (см. таблицу выше) |
| `таймаут (30с)` | Модель не отвечает за 30 секунд | Используйте более быструю модель или платный тариф |
| `API-ключ LLM не задан` | Пустое поле в Настройках | Заполните `OpenAI API key` |
| `не удалось создать OpenAI-клиент` | Пакет `openai` не установлен или старая версия | `pip install -r requirements.txt` |
| `ошибка соединения с LLM` | Нет интернета или провайдер недоступен | Проверьте сеть |

## Кэширование

Описания сохраняются в локальной SQLite по ключу
`SHA256(байты картинки) + модель + промпт`.

- Одна и та же картинка описывается только один раз.
- При смене модели или промпта кэш автоматически становится
  неактуальным - описание будет получено заново.
- БД хранится в `%APPDATA%\MarkItDownGUI\state.db`.

## Технические детали

### Временные файлы

При конвертации PDF/DOCX/PPTX/XLSX приложение извлекает встроенные
картинки в **свежесозданную** пустую папку в `%TEMP%`:

- `%TEMP%\markitdown_gui_pdf_imgs_<rand>\` для PDF
- `%TEMP%\markitdown_gui_office_imgs_<rand>\` для Office

Папка создаётся через `tempfile.mkdtemp` (гарантированно пустая
на момент создания), в неё пишутся только извлечённые картинки, и
в блоке `finally` она удаляется через `shutil.rmtree`. Никакие файлы
вне этой папки не затрагиваются.

### Таймауты

- Один LLM-вызов на картинку - не более 30 секунд. Если модель не
  ответила за это время, картинка получит плейсхолдер
  `> [не удалось получить описание изображения]` и конвертация
  продолжится.
- PDF с N картинками конвертируется не дольше `N * 30 секунд` +
  время на текст. Прогресс в строке файла обновляется после каждой
  картинки - вы видите движение даже на медленных моделях.
